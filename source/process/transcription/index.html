How to turn a BHG site walkthrough recording into notes, a transcript, stills, and glossary updates. First used on 28 August 2026. Follow this for later meetings; don’t skip the stills pass — audio alone mishears names and can’t see “this page”.

Spellings live in glossary. Extend that file as you correct; don’t invent a second glossary per meeting.

What you are producing

One folder per meeting: meetings/YYYY-MM-DD/.

FileJob
meeting-notes.mdThe reliable account: decisions, walkthrough, actions. Write from audio first, then rewrite from stills.
transcript.mdTimestamped diarized transcript. Evidence, not the cleaned story. Light ASR fixes only.
screenshot-timestamps.jsonInclusive grab list {id, t, cue} for extraction.
screenshot-timestamps.mdSame list, human-readable.
stills/JPEGs NNN_HHMMSS.jpg. Working files; prefer not to commit.
phone-stills/JPEGs taken on the phone during the meeting (books, cards, print-outs), not extracted from video. Prefer not to commit.
stills-catalog.mdWhat each cluster of frames actually shows (and what the camera missed). Include phone stills here.
extract_stills.pyOptional local copy; canonical script is <code>extract_stills.py</code> in this folder. Multiple clips need a clip field in the JSON (see 4 Sep).

Also: a row in the meetings index, and any new names/IA in the project glossary. After notes exist, rebuild BHG Site Working (python scripts/build.py in bhgsite-working) so the meeting is on the workshop site.

Do not put in git: the video, extracted wav/mp3 chunks, API keys, or (unless asked) the JPEG stills.

1. Recording

  • Phone video is fine. Audio is primary; the camera is a pointing device.
  • Say at the start that you’re recording so it can be transcribed later.
  • Point at the monitor when someone says “this / there / that map / this list”. You will still miss stretches (desk, clothing, glare). That’s expected — stills tell you which timestamps were useful.
  • Pixel files are often 1920×1080 with a display-matrix rotation (−90). ffmpeg autorotate is the right orientation for a portrait phone filming a landscape monitor. Don’t add an extra transpose unless a test frame is sideways.
  • Keep the original file wherever it landed (Downloads, etc.). Don’t copy 9 GB into docs.
  • Phone stills (covers, cards, print-outs) are part of the evidence. Copy the JPEGs into phone-stills/ if that helps the catalog; don’t skip them because they aren’t in the video.
  • Sequential Pixel clips are separate clocks. Line them up by filename/UTC; don’t smash them into one 00:00 timeline if there is a gap. Label transcript timestamps A / B (or similar).

Probe before transcribing:

ffprobe -v error -select_streams v:0 -show_entries stream=width,height,duration -show_entries stream_side_data=rotation -of json VIDEO.mp4

Note duration, rotation, and (if present) GPS / creation time for the notes header.

2. Audio → first transcript

Keys and models

  • Native OpenAI STT is optional. This machine often has no OPENAI_API_KEY.
  • gpt-4o-transcribe-diarize is not on OpenRouter — don’t wait for it.
  • Use Deepgram Nova-3 via OpenRouter:

POST https://openrouter.ai/api/v1/audio/transcriptions
model deepgram/nova-3
response_format=verbose_json
provider options: diarize, punctuate, utterances, smart_format.

  • OpenRouter key from House of Ur deploy secrets. Never print it. Never commit it.

Chunking

Long files fail or stall. Split to ~8-minute 16 kHz mono wav, then 64 kbps mp3 chunks.

ffmpeg -i VIDEO.mp4 -ac 1 -ar 16000 audio.wav
# then cut into ~480s mp3 pieces

Work in %TEMP%\bhg-meeting-YYYYMMDD\ (or similar). Combined JSON can stay there; only markdown lands in docs.

Speaker IDs

Deepgram labels reset every chunk. Speaker 3:1 is not the same person as Speaker 0:1.

  • In transcript.md, keep Speaker N:M (chunk N, speaker M).
  • Infer typical voices from content, not from IDs, and say so at the top of the transcript.
  • Do not rewrite the whole transcript as named speakers. Guessing will be wrong after the first cut.
  • In meeting-notes.md, use real names (Emlyn / Barbara / Bob, etc.) from what was said.

Transcript conventions

  • Timestamp every utterance: [HH:MM:SS–HH:MM:SS] Speaker N:M.
  • First pass: obvious place-name fixes only (Burra, not Barra/Borrow/Borough) so the file is readable.
  • Leave fillers, false starts, and uncertain words. The notes file is where you interpret.
  • Header must say: model, chunking, speaker-ID warning, link to notes + glossary.

3. First notes (audio only)

Write meeting-notes.md before stills:

  • Header: date, place, attendees, subject, recording filename, STT source.
  • Purpose, decisions, overall reaction.
  • Walkthrough in the order they actually went (not a tidy IA).
  • Cutover must-haves vs later.
  • Action table (who / what).

This pass will be wrong on exact page titles, fake group names, and “this list”. That’s fine. You need the spine so the timestamp list has somewhere to hang.

4. Screenshot timestamps (inclusive)

Read the transcript and list every moment the screen might add information. If in doubt, include it.

Include when someone:

  • navigates (go to, click, back, previous, search)
  • points (this, there, that map, that box, hot link, scroll)
  • names a page, heading, booklet, or person on the page
  • describes a bug you can’t hear (formatting, 404, casino hijack, duplicate rows)

Skip only if the span is clearly not about the screen (long policy talk with no click). Even then, one still at the start of the span is cheap.

Times are on the video clock, same as the transcript. Grab a couple of seconds into the span — they click, then point.

Write both:

{"id": "001", "t": "00:00:08", "cue": "Recording starts; maps / settlement by period"}

and a markdown table. Dense is correct: the 28 Aug pass used 185 grabs on a 73-minute tape.

5. Extract stills

Canonical script: <code>extract_stills.py</code>.

python meetings/extract_stills.py --video "C:\path\to\VIDEO.mp4" --meeting "C:\path\to\docs\projects\bhg-site\meetings\YYYY-MM-DD"

It reads screenshot-timestamps.json, seeks with ffmpeg (-ss before -i), autorotates, scales to 900px wide, JPEG q=3.

Sanity-check rotation on one known screen moment before the full run (four variants: default, -noautorotate, transpose=1, transpose=2). Keep the variant where webpage text is horizontal.

JPEG file size is a proxy:

Size (this pipeline)Likely content
≳ 80 KBReadable monitor
~30–80 KBPartial screen / glare / angle
≲ 30 KBDesk, paper, clothing, covered lens

Don’t describe every dark frame. Catalog the large ones; sample the small ones to confirm they’re useless.

6. Look at the stills (this is the correction pass)

For each useful still, transcribe what is on the page:

  • URL / breadcrumb / heading
  • Visible nav (left menu items, tiles, “In this section”)
  • Exact phrases they were arguing about (Inc., 46 plaques, “Download files available for purchase”, lowercase “indigenous”, “Burra Library”)
  • Names on screen (Rosemary Ros, Mary Warnes, Elizabeth Doidge, Cyndi’s List)
  • Layout bugs (doubled headings, duplicate table rows)

Write stills-catalog.md in two lists:

  1. On the monitor — still id, time, what’s there.
  2. Camera off — don’t pretend you saw Tindale / Features / Mongolata if the frame is a jumper.

When the camera missed, check the rebuild HTML (bhgsite2026/source/...) for the page they named. Creek Street “Vanstone, Hinch” was recovered that way on 28 Aug.

If a still contradicts the transcript (“Cherry and Kidd” vs GURNEY and KNAGGS on screen), keep both: they may have scrolled, or named a nearby heading. Then grep the site — 28 Aug had both headings, and the formatting bug was duplicate HTML blocks.

7. Correct the transcript

Rules:

  1. Glossary wins for established spellings (Burra, Ngadjuri, Ian Auhl, Mary Warnes, Rosemary Ros, Cyndi’s List, Yorke Peninsula).
  2. The still / HTML wins over ASR when the page is in frame (Inc., plaque count, “Burra Family History Group”, book titles).
  3. Don’t “clean up” speech. Only fix tokens that are clearly misheard names, places, or titles.
  4. Record in the transcript header which fixes you applied.
  5. Never remap Speaker N:M to names in the body.

8. Improve the notes

Second pass on meeting-notes.md, driven by the catalog:

  • Replace guessed page titles with on-screen titles and URLs.
  • Quote the exact broken copy (46 plaques, shop prices, “from Burra Library”).
  • Separate must-fix HTML bugs (duplicate surname sections, dead “Download files”) from content opinions.
  • Mark what you didn’t see (Bob’s Nature and Heritage Walk map, Mongolata page).
  • Link stills-catalog.md and the glossary from the Screen / Files section.

The notes remain the document you act on. The transcript stays the raw tape.

9. Glossary

After every meeting, add anything new to glossary:

  • People (attendees and names on pages)
  • Organisations and places
  • Nav / URL patterns
  • Publication titles
  • External-link labels (Useful links)
  • Recurring copy pitfalls

Prefer one row per term. Don’t duplicate the meeting notes. The glossary is for the next transcript, not a second set of minutes.

Companion for Country names: the Ngadjuri language note in planning docs.

10. Index

Add a row to the meetings index. Link notes, stills catalog, glossary. Don’t link the video.

Order of work (checklist)

  1. Probe video; extract wav; chunk; Deepgram via OpenRouter.
  2. transcript.md with Speaker N:M + light Burra-class fixes.
  3. meeting-notes.md from audio (decisions / actions).
  4. Inclusive screenshot-timestamps.json + .md.
  5. Test one still’s rotation; extract all stills.
  6. stills-catalog.md (screen vs missed).
  7. Grep bhgsite2026 HTML for names the stills or ASR are unsure about.
  8. Correct transcript; rewrite notes from catalog.
  9. Update glossary + meetings README.
  10. Leave video, temp audio, keys, and JPEGs out of the commit unless asked.
